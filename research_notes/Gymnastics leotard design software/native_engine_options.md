## 1. Unreal Engine (current release: 5.8)

### Takeaway
Unreal 5.8 (23 June 2026) ships more of the required rendering stack than any other option — Substrate (declared Production-Ready in 5.7, 12 Nov 2025) has built-in fuzz, anisotropy, a second specular lobe, a thin-film helper, specular profiles and a glint lobe; plus Lumen/MegaLights, a path tracer, Nanite and instanced meshes with per-instance data. The counterweights are that the high-end features are gated to Windows DX12/SM6-class GPUs (glints are not rendered on the fallback GBuffer used by mobile; path tracer is Windows/DX12; Mac hardware ray tracing is "Experimental", Nanite on Mac "Beta"), editor tooling may not be shipped inside a product, runtime mesh editing is "Beta", and an application licensed to third parties is royalty-bearing (5% of lifetime gross above $1M).

### Cited Findings

**Versions and status**
- UE 5.7 was published 12 November 2025; Epic's post says: "Another powerful toolset reaching Production-Ready status with this release is Substrate, Unreal Engine's state-of-the-art modular material authoring and rendering framework that offers inherent support for layered and blended materials." — [Epic, "Unreal Engine 5.7 is now available"](https://www.unrealengine.com/news/unreal-engine-5-7-is-now-available)
- Same post: "Substrate empowers creators to combine multiple material behaviors—such as those found in metal, clear coat, skin, and cloth—with true high-quality physical accuracy... And with fine-tuned support for custom shading behaviors, teams can define their own materials logic without hacking the engine." and Substrate "is built to scale all the way down to mobile". The post also carries the footer "Some features are Beta or Experimental, and should not be considered production-ready." — [Epic 5.7 post](https://www.unrealengine.com/news/unreal-engine-5-7-is-now-available)
- UE 5.8 is the current release; Epic's announcement is dated 23 June 2026. Highlights: MegaLights "now Production-Ready, empowering you to place a vast number of dynamic and shadowed area lights"; a new "Lumen Lite mode... Twice as fast as Lumen High Quality... It's also supported on PC"; an Experimental Toon Shader "built on the Substrate framework"; Chaos Cloth Production-Ready. — [Epic, "Unreal Engine 5.8 is now available"](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available)
- 5.8 release notes: Lumen Lite is labelled Beta; mobile now defaults to multi-pass deferred rendering with mobile SSAO/SSR/contact shadows; iOS/iPadOS gain full keyboard and mouse support and Experimental Shader Model 6 support via Apple's Metal Shader Converter targeting A15 and newer. Build requirements: Visual Studio 2026 recommended (VS 2022 17.14 minimum), Windows SDK 10.0.26100 default. — [UE 5.8 release notes](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-5-8-release-notes)
- Secondary reporting (not in Epic's own 5.8 post text that was extracted) says 5.8 is intended as the last UE5 feature release with Unreal Engine 6 previews "late 2027ish", while Epic "do[es] not rule out" a 5.9. — [WN Hub](https://wnhub.io/news/engines/item-51157)
- An independent trade article on 5.7 cautions that, despite "production-ready" designations, Epic's documentation still lists numerous features as Beta or Experimental and advises validating on target hardware. — [Digital Production, 12 Nov 2025](https://digitalproduction.com/2025/11/12/unreal-engine-5-7-foliage-pcg-and-in-editor-ai/)

**Substrate: what it offers for cloth/fuzz, glints, thin-film, anisotropy (Docs 5.8)**
- The Slab BSDF exposes Diffuse Albedo, F0, F90, Roughness, Anisotropy (-1 to 1), Second Roughness + weight (secondary/hazy specular lobe), SSS mean-free-path, and Fuzz Amount / Fuzz Color / Fuzz Roughness (fuzz described as retroreflective fuzz at the interface, usually for fabric). — [Epic, Substrate Materials Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Glints are slab inputs (Glint Density, a logarithmic microfacet density; Glint UVs) and require `r.Substrate.Glints=1`; they fall in the "Complex Special" evaluation set and are not supported on the Blendable GBuffer. — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Thin-film is provided as a "Substrate Thin-Film" helper node that computes F0/F90 from thin-film parameters; Specular Profile is a separate feature (approximated on Blendable GBuffer). — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Layering: Vertical Layer (top/bottom slabs with thickness-based transmittance), Horizontal mixing, Coverage Weight. Cost notes (paraphrased): each additional BSDF roughly doubles the lighting cost for that pixel; a single slab costs about the same as the legacy path; default budget is 80 bytes per pixel. — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Two GBuffer modes. Blendable: fixed footprint, one closure per pixel, performance equal to legacy, but F90, diffusion SSS with per-pixel MFP, haziness and glints "are not rendered". Adaptive: full feature set, ~15% longer cook, runtime regression vs Blendable; available on Xbox Series X/S, PS5, Windows SM6, macOS SM6, Linux SM6 — other platforms (including SM5) fall back to Blendable. On mobile/lower-end, parameter blending is forced. — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- The same 5.8 doc still states "Platform support and testing is currently incomplete", says Mac and DX11 "exhibit issues and may not work entirely", marks opaque rough refraction and material-layer support Experimental, and Path Tracer support for Substrate as Beta. (Tension with the 5.7 "Production-Ready" announcement — sources disagree in tone.) — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)

**Lighting, ray tracing, path tracer**
- Lumen "is developed for next-generation consoles (PlayStation 5, Xbox Series S / X and Switch 2) and high-end PCs"; software ray tracing lists GTX-1070 as minimum; hardware ray tracing needs RTX-2000 / RX-6000 or newer on Windows DX12 or Linux Vulkan; at Epic scalability Lumen costs about 8 ms at 1080p internal resolution on current consoles. Limits: hardware ray tracing is the only way to get high-quality mirror reflections; small meshes are culled from the Lumen Scene (can appear black in mirrors); Lumen is not compatible with the forward renderer. — [Epic, Lumen Technical Details](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine)
- Hardware spec page: Windows recommended = 32 GB RAM, 8 GB+ VRAM, DX12 GPU; Lumen GI/Reflections/MegaLights list AMD RX-6000+, Intel Arc A-series+, or NVIDIA RTX-2000+; Nanite needs DX12 with SM6.6 atomics (or Vulkan equivalent). — [Epic, Hardware and Software Specifications](https://dev.epicgames.com/documentation/en-us/unreal-engine/hardware-and-software-specifications-for-unreal-engine)
- Path Tracer requirements: "Windows 10 1809 or later", DirectX 12, NVIDIA RTX / DXR-enabled GTX cards, hardware ray tracing enabled. It is progressive (accumulates while the camera is still, restarts on camera/material/scene change). Supported shading models include Clear Coat, Cloth, Anisotropy, Thin Translucent; Substrate support is described as initial/experimental; approximate caustics are on by default and refractive caustics converge slowly; spectral dispersion is not mentioned; macOS/Metal/Vulkan are not mentioned. — [Epic, Path Tracer](https://dev.epicgames.com/documentation/en-us/unreal-engine/path-tracer-in-unreal-engine)

**macOS and iPad**
- macOS (Docs 5.8): recommended processor "Apple Silicon M3", minimum "M1 or M2 depending on rendering features"; 16 GB RAM minimum / 32 GB recommended; minimum macOS "Sonoma 14.5". Feature gating: Lumen software ray tracing on M1+; Lumen hardware ray tracing and MegaLights "Apple Sillicon M2+ (Experimental support)"; Nanite and Virtual Shadow Maps "Apple Silicon M2+ (Beta support)". The page does not mention the Path Tracer or Substrate. (The page is internally inconsistent on recommended macOS/Xcode versions, and differs from the SDK table in the release notes.) — [Epic, macOS Development Requirements](https://dev.epicgames.com/documentation/en-us/unreal-engine/macos-development-requirements-for-unreal-engine)
- iOS/iPadOS (Docs 5.8): target SDK iOS/iPadOS 17 or later; iPad (6th gen)+, iPad Air (3rd gen)+, iPad mini (5th gen)+, all iPad Pro; A8/A8X devices unsupported; Xcode 26 required for App Store submission since 28 April 2026. — [Epic, iOS/iPadOS/tvOS Development Requirements](https://dev.epicgames.com/documentation/en-us/unreal-engine/ios-ipados-and-tvos-development-requirements-for-unreal-engine)

**Huge instance counts**
- Nanite: "The maximum number of instances that can be present in the scene is hard-locked to 16 million instances"; only Opaque and Masked blend modes are supported (no translucency, no morph targets); it works with Instanced Static Mesh and Hierarchical ISM components; requires DX12/SM6 on "current console and desktop platforms". — [Epic, Nanite Virtualized Geometry](https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)
- Instanced Static Mesh components carry "Per Instance Custom Data: Additional float data per instance" readable in materials; "on the GPU, a primitive uses roughly ten times more memory than a basic instance (672 bytes vs 64 bytes)"; ISMs cull/LOD each instance on the GPU "which can be expensive on lower powered platforms"; for Nanite-only projects "ISM is always the choice". The page documents no instance-count ceiling and no guidance on frequent runtime updates. — [Epic, Instanced Static Mesh Component](https://dev.epicgames.com/documentation/en-us/unreal-engine/instanced-static-mesh-component-in-unreal-engine)
- 5.7 introduced Experimental Nanite Foliage / "Nanite Voxels, which automatically and efficiently draw millions of tiny, overlapping elements that read as a solid mass at distance". — [Epic 5.7 post](https://www.unrealengine.com/news/unreal-engine-5-7-is-now-available)

**Editor-style interaction at runtime; UI frameworks**
- Slate: "Slate is a completely custom and platform agnostic user interface framework" "designed to make building the user interfaces for tools and applications such as Unreal Editor" efficient; "Slate's docking framework puts the power into the user's hands by allowing its tabbed panels to be rearranged". — [Epic, Slate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/slate-overview-for-unreal-engine)
- Geometry Scripting (runtime mesh generation/editing on `UDynamicMesh`) is labelled Beta with the warning to "use caution when shipping with it"; DynamicMeshComponent updates can run "in-editor and at runtime", but some functions are editor-only, and DynamicMeshComponent does not support Nanite, Lumen, mesh distance fields, LODs or instanced rendering (ray tracing is supported). — [Epic, Geometry Scripting Users Guide](https://dev.epicgames.com/documentation/en-us/unreal-engine/geometry-scripting-users-guide-in-unreal-engine)
- Mesh Paint is documented as an editor mode: "Mesh Paint is a tool for interactively painting colors on meshes and textures in the Editor Viewport." — [Epic, Mesh Paint Mode](https://dev.epicgames.com/documentation/en-us/unreal-engine/mesh-paint-mode-in-unreal-engine)
- The EULA restricts shipping editor code: "If your Product includes Engine Tools, you may only Distribute it through either the Fab Marketplace or through a fork of Epic's GitHub UnrealEngine Network. "Engine Tools" means the (i) editors and other tools included in the Engine Code; (ii) any code and modules in either the Developer or Editor folders, including in object code format, whether statically or dynamically linked; and (iii) other software that may be used to develop standalone products based on the Licensed Technology." — [Unreal Engine EULA §4(d)](https://www.unrealengine.com/eula/unreal)
- Pixel Streaming: the application runs remotely and is streamed over WebRTC to browsers (desktop Chrome/Firefox, iOS, Android); browsers send "keyboard, mouse, and touch events" (pen input is not mentioned); 5.8 moves Unreal Remote onto Pixel Streaming 2. — [Epic, Pixel Streaming Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-pixel-streaming-in-unreal-engine); [UE 5.8 release notes](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-5-8-release-notes)

Standalone Twinmotion seats were priced "$445 per year" in that post. — [Epic pricing post](https://www.unrealengine.com/blog/we-are-updating-unreal-engine-twinmotion-and-realitycapture-pricing-in-late-april)

**Precedent: end-user creative tools on Unreal**
- Twinmotion (real-time archviz; acquired by Epic 2019) ran on its own engine for "more than a decade" and "Two years ago [i.e. ~2017], they switched their underlying engine to Unreal Engine." Product manager Martin Krasemann: "When we decided to change our engine, we quickly saw that Unreal Engine was the most suitable solution on the market." Lead developer Manuel Veit: "With the engine, we have access to all the cutting-edge rendering technologies alongside a very solid development framework. Now we can bring Twinmotion to a higher level both in terms of performance and image quality." The product "leverages the power of Unreal Engine while adding a user-friendly UI, an integrated library... and specially designed architecture-related features". — [Epic blog, 16 Jan 2019](https://www.unrealengine.com/blog/twinmotion-breaks-out-of-the-box-with-a-bridge-to-ue4)
- Architecture today: previously "it was a compiled standalone app — periodically rebuilt from Unreal Engine"; now "Twinmotion runs directly as a specialised instance inside Unreal Engine itself" in "'PIE' or 'Play In Editor' mode". Lumen came first, Nanite arrived in Twinmotion 2025.2, Substrate is planned; Twinmotion Cloud uses pixel streaming so "all the heavy GPU processing is handled in the cloud". — [AEC Magazine, Greg Corke, 2 Dec 2025](https://aecmag.com/visualisation/twinmotion-a-new-chapter/)
- Fashion-adjacent: Style3D publishes "Style3D Simulator", titled "AI Cloth Simulation Plugin for Unreal – Animation & Game". — [Style3D Simulator](https://simulator.style3d.com/en/home)

### Inferences
- Under the quoted terms a leotard design application sold or licensed to outside customers is a "Royalty Product": no seat fees, 5% of that product's lifetime gross above $1M. If instead it is internal-only, built for a single client, or given away to drive leotard sales, it is royalty-free but needs $1,850/seat/yr once the corporate group's revenue plus funding reaches $1M in a 12-month period.
- Substrate's glint lobe exists only on the Adaptive GBuffer, whose platform list is consoles plus SM6 desktop; mobile falls back to Blendable where glints "are not rendered". An iPad build would therefore need a different sparkle technique than the desktop build, on the evidence of the 5.8 docs.
- Twinmotion's current "specialised instance inside the editor" architecture is available to Epic as owner; EULA §4(d) means a third party cannot ship editor modules (Modeling Mode, Mesh Paint Mode) in a standalone product outside Fab/GitHub, so editor-like tools (painting, curve drawing, gizmos, undo) must be rebuilt on runtime modules and Slate/UMG.
- The 16-million-instance cap and GPU-driven ISM path put 10^4–10^6 sequins inside the engine's stated design envelope on DX12-class hardware, but Nanite excludes translucent materials and the docs give no cost data for per-instance updates during painting.
- Hardware targets in Epic's docs (consoles, "high-end PCs", 8 GB VRAM recommended, M2+ for Nanite/hardware RT on Mac) do not address integrated-GPU laptops; meeting requirement 5 on such machines would rely on scalability settings rather than documented support.

### Gaps
- Packaged application size, cold-start time and measured frame rates on integrated GPUs / base Apple silicon: no primary or independent data retrieved.
- Which desktop-class features (Nanite, Lumen, Substrate Adaptive) run on iPadOS M-series: the Mobile Rendering Features page returned no body text.
- Whether a fully custom BRDF (e.g. diffraction) can be added without modifying engine shader source. Epic claims custom shading "without hacking the engine"; the long-standing community view that new shading models need source changes is recalled, unverified.
- Runtime texture painting (render-target based), runtime pen pressure/tilt input, and UMG documentation could not be retrieved; UMG's suitability for dense editor UIs is therefore undocumented here.
- Other third-party creative applications built on Unreal (e.g. D5 Render, product configurators), the Epic–CLO Virtual Fashion share exchange (recalled as 2023) and Marvelous Designer/CLO "LiveSync" to Unreal: not verified in this session.
- Hiring-pool data and independent 2025–2026 post-mortems: not retrieved.

## 2. Unity (current releases: 6.3 LTS, 6.6 "Supported"; Unity 7.0 in alpha)

### Takeaway
Unity's high-fidelity pipeline (HDRP 17.x) has fabric, iridescence, anisotropy, StackLit, AxF car-paint flakes, ray tracing and path tracing, but Unity states that "no new features are planned for HDRP" and that it "strongly encourage[s] using URP when starting any new project" — and URP, the pipeline that runs on iPad, lacks fabric, iridescence, anisotropy, subsurface scattering, real-time area lights and ray tracing. Unity's published real-time glints research is not documented as an HDRP feature. Non-game companies above US$1M "total finances" must use Unity Industry ($4,950/seat/yr), and commercial runtime distribution by Industry customers carries a fee "generally equivalent to 4.0%" of product revenue.

### Cited Findings

**Versions and direction**
- Unity 6.4 (6000.4) is a "Supported" release; ECS packages became core packages. — [Unity 6.4 What's New](https://docs.unity3d.com/6000.4/Documentation/Manual/WhatsNewUnity64.html)
- Unity 6.5: "The Built-In Render Pipeline is deprecated and will be obsolete in a future release." It "remains supported, including bug fixes and maintenance, through the full Unity 6.7 LTS lifecycle." Also: new Panel Renderer component for UI Toolkit, experimental Swift Xcode project type for iOS/iPadOS/tvOS, OptiX denoiser deprecated (removal in 6.7; breaks the temporally-coherent mode with the HDRP path tracer). — [New in Unity 6.5](https://docs.unity3d.com/6000.5/Documentation/Manual/WhatsNewUnity65.html)
- Unity 6.6 (6000.6) is labelled Supported (docs built 13 Oct 2026): WebGPU no longer experimental; "Intel (x86_64) architecture support on macOS is deprecated and will be removed in a future release"; UI Toolkit gains `backdrop-filter` and drop-shadow; domain reload off by default in preparation for the "forthcoming removal of Mono and the domain reload mechanism". — [New in Unity 6.6](https://docs.unity3d.com/6000.6/Documentation/Manual/WhatsNewUnity66.html)
- Unity 7.0 public alpha was announced 5 October 2026 (build 7000.0.0a7); Unity 6.7 LTS is referenced as the supported release preceding 7.0; staff replies state "domain reloads are gone" and that the CoreCLR editor arrives incrementally toward beta. No dates given. — [Unity Discussions, "Unity 7.0 Alpha is now available"](https://discussions.unity.com/t/unity-7-0-alpha-is-now-available/1738310)
- Render-pipeline strategy page: "no new features are planned for HDRP"; maintenance covers "stability, regressions, and critical issues of widely used functionalities"; Unity "strongly encourage[s] using URP when starting any new project"; Built-In stays available through 6.7 LTS with support "at least until the end of 2028" ("and 2029 with Unity Enterprise or Unity Industry licenses"). Planned URP work listed: physical light units, auto exposure, physical sky, real-time GI, screen-space reflections. The page notes HDRP powers archviz, configurators and simulators. No end-of-support date for HDRP is given. — [Unity, "Render Pipelines strategy for 2026"](https://unity.com/topics/render-pipelines-strategy-for-2026)

**URP vs HDRP capability (Unity 6.6 docs)**
- Feature comparison: iOS/Android/WebGL/WebGPU — URP supported, HDRP not supported. Fabric/cloth shading, iridescence, anisotropy, subsurface scattering, translucency, hair — HDRP only. Clear coat — both. Real-time area lights (rectangle, tube, disc) — HDRP only (URP: baked only). Ray tracing and path tracing — HDRP only. Screen-space refraction — HDRP only. AxF — HDRP only. Custom lighting model — URP "not supported", HDRP via a pluggable master node (listed as undocumented). GPU Resident Drawer — both (URP: Forward+/Deferred+ only, off by default; HDRP: on by default). — [Unity, Render pipeline feature comparison](https://docs.unity3d.com/Manual/render-pipelines-feature-comparison.html)
- HDRP 17.3 supported platforms (verbatim list): "Windows and Windows Store, with DirectX 11 or DirectX 12 and Shader Model 5.0", PlayStation 4/5, Xbox One/Series, "MacOS (minimum version 10.13) using Metal graphics", "Linux and Windows platforms with Vulkan". "HDRP only works on these platforms if the device you use supports Compute Shaders." — [HDRP 17.3 System Requirements](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/System-Requirements.html)

**HDRP materials**
- Fabric: a Cotton/Wool shader for "diffuse fabrics such as cotton, wool, linen, or velvet" and a Silk shader for anisotropic fabrics (silk, satin, nylon, polyester); thread maps and fuzz maps supported; the Fabric Master Stack supports subsurface scattering. — [HDRP 17.3, Understand fabrics](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/understand-fabrics.html)
- The Lit shader offers "options for effects like subsurface scattering, iridescence, vertex or pixel displacement, and decal compatibility." — [HDRP 17.3, Lit material](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/lit-material.html)
- StackLit "can render materials that are more complex than the Lit Master Stack", models two vertically stacked physical layers, and computes anisotropic reflections for area lights. — [HDRP 17.3, StackLit](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/stacklit-material.html)
- AxF (X-Rite measured materials): the CAR_PAINT model is a hybrid multi-lobe model with a flakes term driven by a BTF texture array; clearcoat supported. The AxF Importer "is available in Unity Enterprise for Product Lifecycle" or as an unsupported package for Industry customers; without it Unity "does not provide a method to author certain Assets that AxF Materials rely on." — [HDRP 17.3, AxF material reference](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/AxF-material-inspector-reference.html)

**Did Unity's real-time glints research ship?**
- The paper is "Real-Time Rendering of Glinty Appearances using Distributed Binomial Laws on Anisotropic Grids" (Deliot, Belcour et al.; High-Performance Graphics 2023; arXiv 8 June 2023). Abstract: "we render in real-time glittery materials caused by discrete flakes on the surface"; the method runs "1.5X to 5X faster than the state-of-the-art" with "stable performance". — [arXiv 2306.05051](https://arxiv.org/abs/2306.05051)
- The authors' group page distributes the code and demos as Google Drive downloads (no Unity package or repository is listed) and lists no 2024–2026 glint follow-ups. — [GGX Research publications](https://ggx-research.github.io/publications.html)
- That team describes itself as "Now at Intel, previously at Unity." — [GGX Research](https://ggx-research.github.io/)
- The HDRP manual table of contents (17.0) contains no page on glints or sparkle. — [HDRP 17.0 manual TOC](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.0/manual/toc.html)

**Custom lighting**
- Shader Graph's Custom Lighting sample (17.3): "Customizable lighting is only intended to be used when you set the render type to Forward or Forward+"; with Deferred "it's not possible to control the lighting directly in an object's shader"; "To support multiple light sources in Shader Graph, you have to write a small amount of code" because "Shader Graph doesn't support `For` loops". Templates are URP models. — [Shader Graph 17.3, Custom Lighting sample](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.3/manual/Shader-Graph-Sample-Custom-Lighting-Introduction.html)

**Ray tracing / path tracing (HDRP)**
- Ray tracing requirements name Windows 10 1809+ and a list of NVIDIA RTX 20/30, Quadro RTX and AMD RX 6000 cards (GTX 10/16 via fallback); macOS, Metal, Linux, Intel Arc and Apple silicon are not mentioned. — [HDRP 17.3, Ray tracing requirements](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/raytracing-requirements.html)

## 3. Godot (current release: 4.7; 4.7.2 maintenance; 4.8 in feature freeze)

### Takeaway
Godot 4.7 (18 June 2026) is MIT-licensed with no fees, has a retained-mode UI system proven in shipped creative tools, per-light custom BRDF hooks in its shading language, compute/RenderingDevice access and (new in 4.7) rectangular area lights and HDR output — but its standard material has no sheen or iridescence, there is no order-independent transparency, hardware ray tracing is not documented, and screen-space effects/SSS exist only in the desktop Forward+ renderer.

### Cited Findings
- Release timeline: "Godot 4.7 – Lights, Camera, Action!" 18 June 2026; maintenance 4.7.1 (14 July 2026) and 4.7.2 (18 August 2026); 4.8 dev 7 on 29 September 2026 ("Feature freeze has arrived!"). — [Godot blog](https://godotengine.org/blog/)
- 4.7 features: new `AreaLight3D` node (real-time rectangular light); clearcoat reworked to conserve energy and use sky/reflection probes; HDR output on Windows, macOS, iOS, visionOS and Linux (Wayland); `DrawableTexture2D`, "a simpler API for drawing on textures"; Control "offset transforms". — [Godot 4.7 release page](https://godotengine.org/releases/4.7/)
- 4.6 features: LibGodot lets you embed the engine in your own applications and control startup and the engine loop (initial support Linux, Windows, macOS); Direct3D 12 is the default for new Windows projects; SSR overhauled; AgX tonemapper gains white/contrast parameters; glow blends before tonemapping. — [Godot 4.6 release page](https://godotengine.org/releases/4.6/)
- Renderers (Docs 4.7): Forward+ (desktop only) and Mobile use Vulkan, Direct3D 12 or Metal via RenderingDevice; Compatibility uses OpenGL. SSR, SSIL, subsurface scattering, SDFGI/VoxelGI, volumetric fog and TAA/FSR2 are Forward+ only; SSAO is Forward+ and Compatibility but not Mobile; HDR output, compute shaders, RenderingDevice access and CompositorEffects are Mobile and Forward+. Ray tracing is not mentioned. — [Godot docs, Renderers](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)
- StandardMaterial3D (Docs 4.7) offers rim, clearcoat, anisotropy, back lighting, refraction (screen-space; "forces transparency"; cannot refract other transparent materials) and subsurface scattering ("only available in the Forward+ renderer"); sheen and iridescence/thin-film do not appear. - Custom BRDF: the spatial shader `light()` function is called "for every light in every pixel", reads `LIGHT`, `LIGHT_COLOR`, `ATTENUATION`, `VIEW`, `NORMAL`, `ROUGHNESS` etc. and writes `DIFFUSE_LIGHT`/`SPECULAR_LIGHT`; it does not run with vertex lighting. `fragment()` exposes `CLEARCOAT`, `ANISOTROPY`, `SSS_*`, `BACKLIGHT`, `RIM`, plus `RADIANCE`/`IRRADIANCE` outputs that blend with the environment map; no sheen or iridescence built-ins. "Transparent materials also cannot cast shadows or appear in `hint_screen_texture` and `hint_depth_texture` uniforms." — [Godot docs, Spatial shaders](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html)
- Transparency: sorting uses "the Node3D's position, not the vertex position in world space"; on order-independent transparency, "Godot currently doesn't provide this feature". — [Godot docs, 3D rendering limitations](https://docs.godotengine.org/en/stable/tutorials/3d/3d_rendering_limitations.html)
- Instancing: `MultiMesh` gives per-instance transform, colour and a 4-float custom-data value read as `INSTANCE_CUSTOM`; bulk updates through a packed float `buffer`; visibility uses a single user-supplied AABB, so "every single instance will always render" when spread out; no instance limit documented. — [Godot docs, MultiMesh](https://docs.godotengine.org/en/stable/classes/class_multimesh.html)
- Pen input: `InputEventMouseMotion` exposes `pressure` (0–1), `tilt` and `pen_inverted` (the latter implemented on Linux, macOS and Windows). — [Godot docs, InputEventMouseMotion](https://docs.godotengine.org/en/stable/classes/class_inputeventmousemotion.html)
- Real applications built with Godot (official showcase, "Apps & Tools"): Material Maker (procedural material authoring), Pixelorama (pixel-art editor, incl. Web), Dungeondraft (map-making tool), RPG in a Box, ACTION GAME MAKER, Paragraphic, and Xogot ("Godot for iPad & iPhone"). — [Godot showcase](https://godotengine.org/showcase/)
- Material Maker's developer on Godot: he "already loved the nodes approach and how natural the overall design felt" and says it "consistently proves easy and efficient to work with." (Showcase dated October 2019.) — [Godot showcase: Material Maker](https://godotengine.org/showcase/material-maker/)
- Licence: MIT; you may distribute modified or unmodified versions "even commercially and under a different license (including proprietary)"; attribution by including the copyright notice and licence text in documentation; third-party components "are compatible with the terms of Godot Engine's MIT license". — [Godot licence](https://godotengine.org/license/)
- An outside signal of relative maturity: Bevy's own introduction recommends Godot for projects needing a more feature-complete and stable engine today. — [Bevy, Introduction](https://bevy.org/learn/quick-start/introduction/)

### Inferences
- Sheen, thin-film and glint lobes can be written in `light()` for analytic lights, and `RADIANCE`/`IRRADIANCE` can be overridden, but nothing documented lets a shader replace how the built-in pipeline integrates the environment map against a custom BRDF; a faithful image-based response for velvet/iridescence/glitter would need custom pre-filtering or a CompositorEffect/RenderingDevice path.

## 4. Google Filament (current release: v1.78.0)

### Takeaway
Filament is a small, Apache-2.0 physically based forward renderer whose material system already includes a dedicated cloth model, sheen, clear coat, anisotropy, refraction with dispersion and — added in September 2026 — thin-film iridescence, plus a per-light custom shading hook; it runs on Windows, macOS, iOS/iPadOS, Android, Linux and web. It is only a renderer: no editor, no application UI toolkit, no scene tools, no ray tracing — the application layer is entirely the adopter's to build.

### Cited Findings
- Described as a "real-time physically based rendering engine" for Android, iOS, Linux, macOS, Windows and WebGL2; backends: OpenGL 4.1+, OpenGL ES 3.0+, Metal, Vulkan 1.0, WebGPU (Android, Linux, macOS, Windows) and WebGL 2.0. Apache-2.0; "not an officially supported Google product"; 20.6k GitHub stars. — [Filament README](https://github.com/google/filament)
- Feature list: clustered forward renderer; Cook-Torrance specular, clear coat, anisotropy, cloth/sheen, approximated subsurface, custom surface shading; point/spot/directional lights, IBL, cascaded shadows with EVSM/PCSS/DPCF/PCF, contact shadows; SSAO, SSR, screen-space refraction; HDR bloom, depth of field, tone mappers (GT7, PBR Neutral, AgX, ACES, filmic, generic), colour grading, TAA/FXAA/MSAA; glTF 2.0 with clearcoat/transmission/volume extensions. Tools: `matc` material compiler, `cmgen` IBL generator, `filagui` (a Dear ImGui helper), glTF viewer library. — [Filament README](https://github.com/google/filament)
- Release cadence: v1.78.0 on 13 October 2026; v1.77.0 on 15 September 2026 "Adds iridescence properties to the lit shading models" (paraphrase); v1.76.0 added a second specular lobe (`secondRoughness`, `secondRoughnessWeight`) for hazy materials and opt-in multiple directional lights. — [Filament releases](https://github.com/google/filament/releases)
- Material models: Lit, Subsurface, Cloth, Unlit, Specular-glossiness (legacy). Lit layers from outside in: clear coat, sheen, second specular lobe, specular, diffuse. "The clear coat layer effectively doubles the cost of specular computations." Iridescence parameters: `iridescence`, `iridescenceIor` (default 1.3), `iridescenceThickness` (default 400 nm); "Iridescence is not available with the cloth shading model." Refraction: `transmission`, `ior`, `absorption`, `thickness`, `dispersion` ("specified as 20/Abbe number"), with `refractionMode` cubemap or screenspace. — [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- Cloth model: adds `sheenColor` and `subsurfaceColor` and drops metallic/reflectance; "The `subsurfaceColor` parameter should be used with care. High values can interfere with shadows in some areas." — [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- Transparency: blending modes opaque, transparent, fade, add, multiply, screen, masked, custom; transparency modes default / twoPassesOneSide / twoPassesTwoSides, the last of which "lets you render both set of faces while reducing or eliminating sorting issues." — [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- Custom BRDF: with `customSurfaceShading : true` the material implements `surfaceShading`, called once per directional/spot/point light with `MaterialInputs`, `ShadingData` and `LightData` (colour, light vector, NdotL, attenuation, visibility). "Custom surface shading only works with the `lit` shading model." The guide does not describe how it interacts with image-based lighting. — [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- Instancing: materials have an `instanced` option exposing `getInstanceIndex()`. — [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- A user: SceneView (3D/AR SDK) uses "Filament + ARCore on Android, RealityKit + ARKit on Apple, Filament.js + WebXR in the browser." — [SceneView README](https://github.com/SceneView/sceneview-android)

### Inferences
- Of the listed options, Filament's stock material set is the closest raster match to the fabric requirements after Unreal's Substrate and Unity's frozen HDRP: sheen, cloth, anisotropy, clear coat, iridescence (new, one month old at the time of writing), dispersion. Glints/diffraction would be custom code through `surfaceShading`, which covers analytic lights only on the evidence available.
- Everything in requirement 3 (picking, painting, curves, gizmos, undo, docking UI, pen input) and in requirement 6 (installers, updates) sits outside Filament; it would normally be paired with an application framework (Qt, native AppKit/WinUI/UIKit, or Dear ImGui via `filagui`).
- Mobile-first design and the listed OpenGL ES 3.0/Metal backends suggest a low hardware floor, which bears on requirement 5, but no benchmark was retrieved.

- Who else ships on Filament (Google products, Open3D and others are recalled, unverified); any professional design tool built on it: not confirmed.
- Scale limits for instancing (10^5–10^6 instances with per-instance data and partial updates), area-light support, HDR display output: not confirmed from the pages fetched.

## 5. Rust ecosystem (Bevy 0.20, wgpu v30, egui)

### Takeaway
The Rust stack is improving quickly — Bevy 0.20 shipped 8 October 2026 with GPU-driven rendering, a real-time path-traced lighting crate (Solari) and a growing tooling widget set — but its own maintainers say "Important features are missing", breaking releases land roughly every three months, the first-party editor and several UI basics (undo/redo in text fields, HDR display output) are still upcoming, and the standard material has neither sheen nor thin-film. wgpu is a credible low-level portability layer (Vulkan/Metal/DX12/GLES/WebGPU) with ray-tracing and HDR-surface APIs arriving in 2026.

### Cited Findings
- Release history: Bevy 0.17 (30 Sep 2025), 0.18 (13 Jan 2026), 0.19 (19 Jun 2026), 0.20 (8 Oct 2026). — [Bevy news](https://bevy.org/news/)
- Maturity statement: "Bevy is still in development. Important features are missing, and documentation can be sparse." "A new version of Bevy containing breaking changes to the API is released approximately once every 3 months." "Use only if you are willing to work in this environment." — [Bevy, Introduction](https://bevy.org/learn/quick-start/introduction/)
- `StandardMaterial` (0.20): base colour, metallic/roughness, reflectance, specular tint, diffuse and specular transmission with thickness/IOR/attenuation, clearcoat (+roughness, normal), anisotropy strength/rotation, parallax; alpha modes Opaque, Mask, Blend, Premultiplied, Add, Multiply. There are no sheen and no iridescence/thin-film fields. — [docs.rs, bevy 0.20 StandardMaterial](https://docs.rs/bevy/latest/bevy/pbr/struct.StandardMaterial.html)
- Solari: introduced in 0.17 as an experimental crate — "it is not yet production ready"; its real-time mode then needed DLSS Ray Reconstruction (NVIDIA RTX, Vulkan on Windows/Linux). 0.18 calls it "Bevy's experimental real-time raytraced renderer" and adds specular. 0.20: lighting "mostly unbiased", runs on macOS without a built-in denoiser, DLSS-RR 4.5 via `dlss_wgpu`. — [Bevy 0.17](https://bevy.org/news/bevy-0-17/); [Bevy 0.18](https://bevy.org/news/bevy-0-18/); [Bevy 0.20](https://bevy.org/news/bevy-0-20/)

- UI/tooling: Feathers is "an experimental new widget library for building tooling" (0.18); 0.19 adds `EditableText` where "Many important features are currently unimplemented" (placeholder text, undo/redo, password masking); 0.20 adds colour input, list view, dropdown and menu widgets. - wgpu: latest v30.0.1 (22 Aug 2026); v30.0.0 (1 Jul 2026) adds HDR/wide-gamut surface configuration (Vulkan, DX12, Metal) and BLAS support for procedural geometry; v29.0.0 (19 Mar 2026) adds TLAS binding arrays; v28.0.0 (18 Dec 2025) mesh shaders "fully supported on Vulkan, and supported on Metal and DX12 with passthrough shaders". Three breaking major versions in roughly seven months. — [wgpu releases](https://github.com/gfx-rs/wgpu/releases)
- egui: goals are "The easiest to use GUI library"; non-goals include "Become the most powerful GUI library" and "Native looking interface"; "New releases will have breaking changes"; "If you want something that doesn't break when you upgrade it, egui isn't for you (yet)"; layout is "a fundamental shortcoming of immediate mode GUIs"; built-in colour picker and drag values; optional AccessKit; "egui development is sponsored by Rerun"; MIT/Apache-2.0; 31.4k stars. — [egui README](https://github.com/emilk/egui)

- For this product Bevy would supply ECS, asset handling, windowing and a renderer skeleton, while the fabric lobes (sheen, thin-film, glints), sheer transparency strategy and most editor UI would be custom — closer in effort to "hand-rolled on wgpu with helpers" than to adopting a finished engine.

## 7. Hand-rolled renderer plus application framework; libraries that reduce the effort

### Takeaway
A custom stack gives complete control of the lighting loop, transparency strategy and hardware floor, and is the route several long-lived professional tools took, but it means building the renderer, editor interactions, UI, asset pipeline and distribution — the one sourced data point (Shapr3D) puts "solid foundations" for a professional 3D design tool at three years. Middleware narrows the gap: bgfx, Diligent Engine, The Forge, Dawn/wgpu abstract the graphics APIs; Qt supplies the desktop/tablet application shell (and Qt Quick 3D offers a mid-level renderer with documented custom-lighting hooks, under GPLv3 or commercial terms).

### Cited Findings
- bgfx: "Cross-platform, graphics API agnostic, "Bring Your Own Engine/Framework" style rendering library"; backends Direct3D 11/12, Metal, OpenGL 4.3+/ES 3.0+, Vulkan, WebGL 2.0, WebGPU (Dawn Native); platforms include Windows, macOS, iOS/iPadOS, Android, Linux, Wasm; BSD-2-Clause; 17.6k stars; listed users include HARFANG 3D (a visualisation framework with its own editor) and cmftStudio. — [bgfx README](https://github.com/bkaradzic/bgfx)
- Diligent Engine: a "lightweight, high-performance graphics API abstraction layer" with D3D11/D3D12/Vulkan/OpenGL/WebGPU and Metal; Apache 2.0, except the Metal backend is "Available under commercial license - please contact us for details" (Vulkan via MoltenVK is the open path on Apple); features "Ray-tracing, mesh shaders, tile shaders, bindless resources"; DiligentFX adds a PBR renderer, shadows, SSAO/bloom/TAA; Dear ImGui integration; listed users include Bentley Systems (LumenRT) and Elbit Systems. — [Diligent Engine README](https://github.com/DiligentGraphics/DiligentEngine)
- The Forge (ConfettiFX): cross-platform C/C++ framework (Windows DX12, macOS/iOS Metal, Android Vulkan, consoles) that is "a core part of our service business"; Apache 2.0 for open platforms; ray queries, visibility buffer, Dear ImGui-based UI, FSL shading language. Status: latest dated release 1.63 (20 March 2025); "Development will now happen in our internal repositories only" and the repository is marked "Continued on https://codeberg.org/The-Forge". Credits list Hades and the Hypixel engine as custom engines built with its building blocks. — [The Forge README](https://github.com/ConfettiFX/The-Forge)
- Dawn: "an open-source and cross-platform implementation of the WebGPU standard" and "the underlying implementation of WebGPU in Chromium"; backends "D3D12, Metal, Vulkan and OpenGL"; provides `webgpu.h` and the Tint WGSL compiler; BSD 3-Clause; "This is not an officially supported Google product." — [Dawn README](https://github.com/google/dawn)
- wgpu (Rust, with C bindings via wgpu-native) is the other WebGPU-style native layer; see section 5. — [wgpu releases](https://github.com/gfx-rs/wgpu/releases)
- Qt Quick 3D (Qt 6.12 docs): "Qt Quick 3D is available under the commercial license from The Qt Company." "In addition, it is available under the GNU General Public License, version 3." Guides cover PBR, image-based lighting, instanced rendering, custom geometry, lightmaps and custom post-processing. — [Qt Quick 3D](https://doc.qt.io/qt-6/qtquick3d-index.html)
- Qt Quick 3D `CustomMaterial` (shaded mode) lets a material override `DIRECTIONAL_LIGHT`, `POINT_LIGHT`, `SPOT_LIGHT`, `AMBIENT_LIGHT`, `SPECULAR_LIGHT`, `IBL_PROBE` (which adds "both the diffuse and the specular contributions of IBL") and `POST_PROCESS`; instancing exposes `INSTANCE_DATA` (vec4 per instance), `INSTANCE_COLOR`, `INSTANCE_INDEX`; `SCREEN_TEXTURE`/`DEPTH_TEXTURE` cover opaque content only. — [Qt, CustomMaterial](https://doc.qt.io/qt-6/qml-qtquick3d-custommaterial.html)
- Qt Quick 3D `PrincipledMaterial` (6.12 reference, as summarised by the fetch) lists clearcoat, transmission/thickness/attenuation, IOR and specular tint, and no fuzz/sheen, iridescence or anisotropy properties. — [Qt, PrincipledMaterial](https://doc.qt.io/qt-6/qml-qtquick3d-principledmaterial.html)
- Qt tablet input (`QTabletEvent`, 6.12): pressure, tangential pressure, rotation (incl. Apple Pencil), x/y tilt, z; on Windows the page says tablet support "currently requires the WACOM windows driver". — [Qt, QTabletEvent](https://doc.qt.io/qt-6/qtabletevent.html)
- Qt is the DCC-industry baseline: the VFX Reference Platform (which aims to "establish a consistent build target for software providers") specifies Qt 6.8.x and PySide 6.8.x for CY2026 and CY2027. — [VFX Reference Platform](https://vfxplatform.com/)
- Dear ImGui is "designed to enable fast iterations" and to "empower programmers to create content creation tools and visualization / debug tools" as opposed to "UI for the average end-user"; it "lacks certain features commonly found in more high-level libraries"; full internationalisation and "accessibility features are not supported"; docking and multi-viewport live in the `docking` branch; MIT; 76.6k stars. — [Dear ImGui README](https://github.com/ocornut/imgui)
- Renderer-only libraries with fabric lobes built in (Filament) are covered in section 4; Hydra/OpenUSD in section 6.
- Why tool makers went custom, in their own words: Shapr3D "took three years to establish solid foundations" because "building an industrial-grade CAD system proved extremely challenging"; it later replaced the open-source Open Cascade kernel with licensed Parasolid (December 2017). — [Shapr3D, Brief history (28 Jul 2025)](https://www.shapr3d.com/blog/brief-history-of-shapr3d)
- The opposite move: Twinmotion abandoned its own engine after a decade — "When we decided to change our engine, we quickly saw that Unreal Engine was the most suitable solution on the market." — [Epic blog, 16 Jan 2019](https://www.unrealengine.com/blog/twinmotion-breaks-out-of-the-box-with-a-bridge-to-ue4)
- 3DESIGN (jewellery CAD) advertises being "developed as an independent 3D engine" and "not a solution based on Rhino"; the competing MatrixGold is sold as a layer on Rhino 8. — [3DESIGN](https://3design.com/); [Gemvision MatrixGold](https://gemvision.com/matrixgold)

### Inferences
- "Hand-rolled" is a spectrum: (a) raw Vulkan/D3D12/Metal ×3; (b) one WebGPU-style or bgfx/Diligent abstraction with a custom renderer on top; (c) a renderer library such as Filament or Qt Quick 3D with custom materials; each step down trades control for less code. The custom-BRDF requirement is satisfiable at every level; the differences are in how much of the editor/UI/distribution layer comes for free (Qt: most of it; ImGui: tool-grade UI only; none with bare graphics APIs).
- Licence traps exist even here: Qt Quick 3D is GPLv3-or-commercial (not LGPL), Diligent's native Metal backend is commercial, The Forge's public development has largely moved in-house.
- The tools that chose custom engines in the case studies below (ZBrush, Procreate, Nomad Sculpt, Shapr3D, KeyShot, CLO/Marvelous Designer, 3DESIGN) share a pattern: a narrow, deep core competency (sculpting, painting, CAD kernel, cloth simulation, ray tracing) that general engines did not provide, and in several cases tablet-first performance targets.

### Gaps
- Qt commercial pricing (the pricing URL returned only FAQ text), and whether the Wacom-driver statement still reflects Qt 6.12 behaviour with Windows Ink: not confirmed.
- No credible effort data (person-years, team size) for building a comparable renderer plus editor from scratch beyond the Shapr3D statement; no post-mortems retrieved.
- Slang, MoltenVK, SDL3 GPU, NVRHI, O3DE, Ogre-Next, Magnum, VTK and similar candidates were not evaluated.

It suits a prototype or pipeline tool more obviously than a polished, proprietary end-user application; that is a reading of the documented limits, not a vendor statement.
- The iPad-first tools examined (Procreate, Nomad Sculpt, Shapr3D, ZBrush for iPad) all use proprietary engines; no iPad professional creative tool built on Unreal or Unity was identified in this session (absence of evidence, given the search constraint).

## 9. Hardware ray tracing: would it materially help, and where is it turn-key?

### Takeaway
The sources support a split answer: sparkle from sequins/glitter is addressed by real-time procedural glint BRDFs that need no ray tracing (Unity research; Unreal's Substrate glints), whereas faceted crystals and layered transparent objects are where vendors reach for ray tracing (Unity's recursive rendering, KeyShot's gem material, Unreal's note that only hardware ray tracing gives high-quality mirror reflections). Turn-key ray/path tracing exists in Unreal, Unity HDRP and Omniverse but is tied to Windows DX12/RTX-class hardware; on Apple silicon it is experimental (Unreal) or absent from the docs (Unity), and it is experimental in Bevy.

### Cited Findings
- Glints without ray tracing: the Deliot–Belcour method renders "in real-time glittery materials caused by discrete flakes on the surface" by counting reflecting flakes per pixel footprint, with "stable performance" and "1.5X to 5X faster than the state-of-the-art". — [arXiv 2306.05051](https://arxiv.org/abs/2306.05051)
- Unreal exposes glints as Substrate slab inputs in the raster path (Adaptive GBuffer only). — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Unreal: hardware ray tracing is the only way to get high-quality mirror reflections in Lumen; small meshes are culled from the Lumen Scene and can appear black in mirrors unless hit lighting is used. — [Lumen Technical Details](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine)
- Unreal Path Tracer: Windows + DX12 + RTX-class; progressive (not a constant-frame-rate mode); refractive caustics converge slowly; Substrate support experimental/Beta; Cloth, Clear Coat, Anisotropy and Thin Translucent supported. — [Path Tracer](https://dev.epicgames.com/documentation/en-us/unreal-engine/path-tracer-in-unreal-engine)
- Unreal on Mac: Lumen hardware ray tracing and MegaLights are "Experimental support" on M2+. — [macOS Development Requirements](https://dev.epicgames.com/documentation/en-us/unreal-engine/macos-development-requirements-for-unreal-engine)
- Unity HDRP: ray tracing documented for Windows with listed NVIDIA/AMD cards; path tracing "only... on platforms that use DX12"; Recursive Rendering targets multi-layered transparent objects with multi-bounce reflection and refraction; URP has no ray tracing. — [Ray tracing requirements](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/raytracing-requirements.html); [Path tracing limitations](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/path-tracing-limitations.html); [Recursive rendering](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.3/manual/Ray-Tracing-Recursive-Rendering.html); [Feature comparison](https://docs.unity3d.com/Manual/render-pipelines-feature-comparison.html)
- Omniverse: RTX rendering with a GeForce RTX 3070 minimum; non-RTX GPUs unsupported. — [Omniverse technical requirements](https://docs.omniverse.nvidia.com/dev-guide/latest/common/technical-requirements.html)
- Bevy Solari: real-time path-traced lighting, labelled experimental in 0.17/0.18, improved in 0.19/0.20; best denoising via DLSS Ray Reconstruction (NVIDIA). wgpu exposes acceleration-structure APIs (TLAS binding arrays in v29, procedural-geometry BLAS in v30). — [Bevy 0.18](https://bevy.org/news/bevy-0-18/); [Bevy 0.20](https://bevy.org/news/bevy-0-20/); [wgpu releases](https://github.com/gfx-rs/wgpu/releases)
- Raster-only renderers and their stated limits: Blender EEVEE has no ray-triangle intersection, models one refraction event correctly and cannot ray-trace blended materials; Godot's refraction is screen-space and its docs do not mention ray tracing; Filament offers cubemap or screen-space refraction with a dispersion parameter and no ray tracing in its feature list. — [EEVEE limitations](https://docs.blender.org/manual/en/latest/render/eevee/limitations/limitations.html); [Godot StandardMaterial3D](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html); [Filament Materials guide](https://google.github.io/filament/main/materials.html)
- Professional visualisation tools pair a real-time mode with a ray-traced mode: Stager's Mercury engine switches "between real-time rendering and ray tracing"; KeyShot offers CPU ray tracing and an OptiX GPU mode. — [Adobe Stager](https://www.adobe.com/products/substance3d/apps/stager.html); [KeyShot GPU Mode](https://manual.keyshot.com/manual/gpu-mode/)
- Apple's Metal page lists ray tracing among debuggable pipeline stages and promotes MetalFX "Upscaling, Frame Interpolation, and Denoising"; Metal 4 is supported on Apple silicon Macs (M1 or later) and A14 Bionic or later. — [Apple, Metal](https://developer.apple.com/metal/)

### Inferences
- Likely benefit by feature: crystals (multi-bounce internal reflection/refraction, dispersion, accurate reflections of surroundings) gain most; sequins gain modestly (true inter-reflection and occlusion between overlapping discs; mirror-like reflection of the environment) because their dominant cue — sparkle — is a BRDF/statistics problem; sheer mesh gains correct layering and shadowing through transparency but is chiefly a transparency-ordering and transmission-model problem that rasterisers handle with OIT/dithering rather than rays.
- Making ray tracing a baseline would exclude the integrated-GPU and iPad targets in requirement 5/6 on current evidence; the pattern in shipping tools is a raster interactive mode plus an optional ray/path-traced "beauty" mode on capable hardware.
- "Turn-key" ranking by documentation: Unreal (Lumen HWRT + path tracer, Windows; experimental Mac), Unity HDRP (Windows DX12; pipeline frozen), Omniverse RTX (RTX-only). Everything else requires building on raw ray-tracing APIs (wgpu, Metal, DXR/Vulkan RT) or has none.

### Gaps
- No measured comparisons of raster-approximated vs ray-traced gems/sequins at interactive rates were retrieved; the feature-by-feature benefit above is inference.
- Which Apple chips have hardware-accelerated ray tracing (recalled: A17 Pro and M3 onward) was not confirmed on the page fetched.
- Spectral dispersion in Unreal's path tracer and gem-specific materials in Unreal/Unity: not documented in the pages read.

## 10. Cost and time: licences, seats, and data on effort

### Takeaway
Direct licence cost ranges from zero (Godot, Filament, Bevy/wgpu/egui, bgfx, Dawn, Omniverse as of May 2026) through per-seat subscriptions (Unity Pro $2,310, Unity Industry $4,950, Unreal $1,850 for non-royalty uses) to revenue shares (Unreal 5% above $1M product revenue; Unity roughly 4% runtime fee for Industry customers). Credible published data on time-to-prototype or team size for comparable tools is almost absent; the few data points suggest multi-year foundations for custom engines.

### Cited Findings
- Unreal: free under $1M (source included); 5% royalty on lifetime gross above $1M for an application "that relies on engine code at runtime and will be licensed to third party end users"; otherwise "$1,850 per seat per year" for companies over $1M in the past 12 months; Epic Pro Support optional at ≥10 seats. — [Epic, Licensing](https://www.unrealengine.com/license)

- Godot: MIT, no royalties or fees mentioned; attribution required. — [Godot licence](https://godotengine.org/license/)

### Inferences
- Illustrative licence arithmetic for a five-developer company, using only the quoted list prices: Unreal — $0 while company revenue+funding is under $1M; if the tool is sold to customers, then 5% of product revenue beyond the first $1M (e.g. $50,000 on $2M lifetime gross). Unity — Pro 5 × $2,310 = $11,550/yr once above $200K; if classed as an Industry customer above $1M, 5 × $4,950 = $24,750/yr plus about 4% of product revenue. Godot/Filament/Rust/custom — $0 licence, with Qt commercial pricing unknown if Qt is used.
- For the open-source and custom routes the dominant cost is engineering time for the editor/UI/material layers; for the engine routes it is licence/royalty plus adapting game-oriented tooling (and, for Unreal, replacing editor-only tools that cannot be shipped).

## 11. Cross-option evaluation against the seven requirements

### Takeaway
No option satisfies all seven requirements out of the box: the engines with the richest shipped material and lighting features (Unreal, Unity HDRP, Omniverse) have the highest hardware floors and weakest iPad story, while the lightweight, permissively licensed options (Godot, Filament, Rust, custom) reach modest hardware and tablets but leave more of the fabric shading and/or the editor application to be built.

### Cited Findings
- Unreal's glint lobe requires the Adaptive GBuffer (consoles, SM6 desktop); glints "are not rendered" on the Blendable fallback used elsewhere. — [Substrate Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-substrate-materials-in-unreal-engine)
- Unity: HDRP has fabric/iridescence/anisotropy/ray tracing but "no new features are planned"; URP supports iOS but lacks those features. — [Unity strategy](https://unity.com/topics/render-pipelines-strategy-for-2026); [Feature comparison](https://docs.unity3d.com/Manual/render-pipelines-feature-comparison.html)
- Godot: no sheen/iridescence built-ins, no order-independent transparency; per-light `light()` hook; MIT. — [Spatial shaders](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html); [3D rendering limitations](https://docs.godotengine.org/en/stable/tutorials/3d/3d_rendering_limitations.html)
- Filament: cloth, sheen, anisotropy, clear coat, iridescence (since v1.77.0), dispersion; renderer only. — [Filament Materials guide](https://google.github.io/filament/main/materials.html); [Filament releases](https://github.com/google/filament/releases)
- Bevy: "Important features are missing"; no sheen/iridescence in `StandardMaterial`. — [Bevy Introduction](https://bevy.org/learn/quick-start/introduction/); [StandardMaterial](https://docs.rs/bevy/latest/bevy/pbr/struct.StandardMaterial.html)
- Omniverse: RTX 3070 minimum; Windows/Linux only. — [Omniverse technical requirements](https://docs.omniverse.nvidia.com/dev-guide/latest/common/technical-requirements.html)
- Qt Quick 3D: overridable light and IBL functions; GPLv3 or commercial. — [CustomMaterial](https://doc.qt.io/qt-6/qml-qtquick3d-custommaterial.html); [Qt Quick 3D](https://doc.qt.io/qt-6/qtquick3d-index.html)
